# Roadmap

| Phase | Implementation backlog | Acceptance criteria |
| --- | --- | --- |
| 0. Foundation | Define product, architecture, contracts, security and experiment design. Add Python package, health endpoint and smoke test. | All specified files exist, Windows Python 3.12 checks pass and a review branch is prepared. |
| 1. Identity and evidence | Implement strict manifest and evidence schemas, canonical encoding, SQLite registries and baseline comparison. | Golden fingerprints reproduce on fresh Windows installs. Changing any required component changes the fingerprint. Duplicate registration is idempotent. Candidate comparisons identify each changed component. Cross-candidate and tampered artifacts fail verification. |
| 2. Deterministic governance | Implement versioned YAML policies, deterministic assessment, scoped approval and audit history. | Mandatory failures and missing or unverifiable evidence block approval. Policy changes invalidate stale approval attempts. Unauthorized and concurrent requests cannot bypass the gate. Audit queries reconstruct each decision. Full deterministic workflow requires no paid API. |
| 3. Advisory review and UI | Add provider-independent adapter and fake, then a lightweight local review UI with baseline changes, reasons, findings and human decision. | Fake adapter tests need no credentials. Malformed advice, provider failure and evidence instructions leave the deterministic gate authoritative. Eligible and approved appear as distinct states in the UI. |
| 4. Comparative experiments | Version synthetic cases and labels, add the experiment runner and an independent secondary reviewer. | Run all four arms against common fixtures, publish the seven requested metrics and replay metadata, and verify mandatory gate invariants in C and D. |
