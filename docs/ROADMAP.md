# Roadmap

| Phase | Implementation backlog | Acceptance criteria |
| --- | --- | --- |
| 0. Foundation | Define product, architecture, contracts, security and experiment design. Add the Python scaffold, smoke test, CI, initial synthetic cases and license recommendation. | Review suite versioning, change categories and risk tiers. Verify at least 20 labeled cases and proposed success criteria. Pass Python 3.12 dependency and test checks. Keep license selection with the maintainer. |
| 1. Identity and evidence | Implement versioned manifest, suite and evidence schemas, structured operating scope, canonical encoding, SQLite registries and classified baseline comparison. Expose and test HTTP registration, retrieval, comparison and verification. | Golden fingerprints reproduce on Windows and Linux. Runtime and scope changes alter candidate identity while administrative and suite-only changes preserve it. Duplicate registration is idempotent. Comparisons retain overlapping categories. Strict HTTP intake rejects invalid and duplicate-key JSON. Cross-candidate evidence, altered metadata and tampered artifacts fail verification. |
| 2. Deterministic governance | Implement versioned YAML policies, risk classification, deterministic assessment, scoped approval, audit history, and REST endpoints. | Risk and change rules resolve mandatory controls. Missing, unverifiable and retired-suite evidence blocks applicable checks. Policy changes invalidate stale approval attempts. Unauthorized and concurrent requests cannot bypass the gate. Audit queries reconstruct each decision. All 22 synthetic cases and Phase 1 regression tests pass without a paid API. |
| 3. Advisory review and UI | Add provider-independent adapter and fake, then a lightweight local review UI with baseline changes, reasons, findings and human decision. | Fake adapter tests need no credentials. Malformed advice, provider failure and evidence instructions leave the deterministic gate authoritative. Eligible and approved appear as distinct states in the UI. |
| 4. Comparative experiments | Version synthetic cases and labels, add the experiment runner and an independent secondary reviewer. | Run all four arms against common fixtures, publish the seven requested metrics and replay metadata, and verify mandatory gate invariants in C and D. |
